## 2. 可信度口径

- **高**：医院官网、北京市政府或现行法律原文直接支持，且无更新版本冲突。
- **中高**：官方来源直接支持，但属于时间敏感规则，或结论含有限度推断。
- **中**：公开技术观察或“未发现”类结论，需要后续人工/真实会话复核。
- **低**：只有第三方来源。本文不以低可信度来源确定放号规则。

所有下列结论的核验日期均为 **2026-07-19**。

## 4. “公开稳定实时号源 API”判断

### 4.1 判定标准

只有同时满足以下条件，才标为“公开稳定实时号源 API”：

1. 官方明确面向第三方开发者开放；
2. 有公开接口文档、鉴权和使用条款；
3. 返回可预约状态或余量，而非仅医生排班；
4. 有版本、频控/配额或服务承诺；
5. 不依赖患者 Cookie、Token、设备签名或小程序私有上下文。

### 4.2 结果

| 来源 | 官方公开排班 | 公开实时余号 | 文档化第三方 API | 结论 | 可信度 |
|---|---:|---:|---:|---|---|
| 同仁官网 | 部分，且当前页可能空 | 否 | 未发现 | 可做规则/排班参考，不可做实时号源 API | 高/中高 |
| 协和官网 | 是，未来一周医生排班 | 否 | 未发现 | 首版排班适配器最佳来源 | 高 |
| 北大一院官网 | 科室/医生信息为主 | 否 | 未发现 | WAF/TLS 进一步降低无人值守稳定性 | 高 |
| 北京 114 / 京通 | 患者端可看号并预约；医院与平台有机构直连 | 未向匿名第三方开放 | 未发现 | 机构直连不等于开发者 API；当前以公众号/小程序为主 | 高 |

**总判断：`public_realtime_availability_api = false`。** 这不表示医院内部没有接口，只表示没有找到可供本开源项目合法、稳定直接调用的公开接口。  
证据：[北京市管理规范](https://wjw.beijing.gov.cn/zwgk_20040/zcwj2024/202405/t20240510_3670669.html)、[114 覆盖说明](https://www.beijing.gov.cn/hudong/bmwd/jsjbmyyt/2024jmwd/2024jmwd3/202411/t20241127_3951351.html)及上述三院官方页面。核验：2026-07-19。**可信度：中高**。

## 5. 可合法实现的数据接入等级、频率与风险

> 下表频率是保守工程上限，不是“低于该频率就当然合法”的安全港。若官方条款、页面提示或技术响应要求更低频，应以更严格者为准。

| 等级 | 可接入内容 | 建议频率 | 风险 | 实现要求 |
|---|---|---|---|---|
| **A0：官方规则元数据** | 医院公告、放号时间、预约天数、官方入口、候补规则、院区/科室字典 | 每 24 小时一次；已发布规则可每 7 天复核；放号时段无需加速 | 低 | 条件 GET/内容哈希；保存来源 URL、页面发布日期和最后核验时间；不得镜像大段受版权保护内容。 |

## 6. 首版真实适配器与 fallback

### 6.1 推荐顺序

1. **GO：`PumchPublicScheduleAdapter`（A1）**  
   - 数据：协和东单/西单皮肤科未来 7 天医生、日期、时段、排班哈希。  
   - 能产生：`schedule_released`、排班新增/取消。  
   - 不能产生：`availability_changed_to_available`、`cancellation_slot_detected`。  
   - 访问方式：本机原生 Browser Agent 打开官方顶层出诊页并读取渲染 DOM；不使用 Docker，不直接绑定未文档化站内片段 URL。  
   - 证据：[协和皮肤科周出诊](https://www.pumch.cn/expert_chuzhen_week/%E7%9A%AE%E8%82%A4%E7%A7%91/3/1.html?linkage=990473)。核验：2026-07-19。**可行性：高**。

2. **CONDITIONAL GO：`PumchLocalBrowserAvailabilityAdapter`（B）**  
   - 在用户主动登录官方 PC 医疗服务页后，只读科室列表中的可见状态并向本机返回脱敏结果。  
   - 开发前置验收：登录后可由扩展读取稳定语义 DOM；无强制小程序跳转；不需读取网络响应或 Token；官方页面未禁止该类本地辅助；连续 7 天低频运行不触发验证码/频控。  
   - 任一条件不满足即降级，不得改走私有接口。  
   - 证据：[协和 PC 医疗服务入口](https://pumchapp.pumch.cn/pages/pc/home/index)。核验：2026-07-19。**可行性：中**。

3. **首版 NO-GO：同仁/北大一院无人值守实时余号适配器**  
   - 同仁主要在微信小程序/114，官网排班页不足以证明余号；北大一院主要在实名患者渠道，且本次官网自动访问存在 WAF/TLS 问题。  
   - 证据：[同仁预约说明](https://www.bjtrhos.cn/Html/News/Articles/7104.html)、[北大一院预约流程](https://pkufh.91health.net/Html/News/Articles/54811.html)。核验：2026-07-19。**可信度：高**。

### 6.2 降级链

1. A1 公开排班可用：展示排班和变更；
2. B 本地 Browser Agent 可用：展示用户页面实际可见的有号/已满；
3. 出现登录过期、验证码、403/418/429、DOM 改版或结果不完整：状态改为 `unknown`，暂停自动检查，提示用户打开官方页面；
4. 同仁、协和已满：优先提示使用官方候补；
5. 仅小程序可查：保留规则日历、放号前 5 分钟提醒和官方入口，不监控退号；
6. 所有真实源不可用：继续提供带“演示数据”水印的测试流，绝不把演示结果标成真实号源。

### 6.3 本地、无 Docker 的发布形态

- 原生本机进程 + 浏览器扩展；服务只绑定 `127.0.0.1`，默认不监听局域网。
- 首版固定使用本地 SQLite（`better-sqlite3`），不提供 PostgreSQL 选项，避免为单用户本地版引入外部数据库或 Docker。
- 默认关闭 B 级适配器；逐医院显式授权、逐域白名单。
- 无遥测、无云端账号、无远程控制面；更新检查也不得上传医院 URL、关注任务或会话信息。
- 扩展仅发送派生字段：`hospital/campus/department/doctor_or_title/date/period/status/observed_at/source_url`。

该形态能显著减少账号上云和个人信息泄露风险，但**“只在本地”并不自动免除第三方服务条款、网络安全或个人信息保护义务**。依据：[个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)、[网络数据安全管理条例](https://www.gov.cn/zhengce/zhengceku/202409/content_6977767.htm)。核验：2026-07-19。**可信度：高**。

## 7. 开源发布必须出现的合规文案

建议在 README、首次启动页、扩展商店说明和“关于/数据来源”页同时展示以下文案：

> **独立性声明**  
> 本项目是独立开源的本地信息提醒工具，与北京同仁医院、北京协和医院、北京大学第一医院、北京 114、京通及其技术服务商不存在隶属、授权、合作或代理关系。医院、平台名称及商标归各权利人所有，仅用于识别公开信息来源。
>
> **功能边界**  
> 本项目不提供自动抢号、自动预约、自动取号、验证码识别、自动提交、自动支付、多账号并发、代理 IP 轮换或风控绕过。预约、实名核验、医保确认和支付必须由用户在官方渠道人工完成。
>
> **数据与隐私**  
> 本项目默认仅在用户本机运行，不上传医院 Cookie、Token、账号密码、身份证号、医保卡号、病历或其他医疗健康信息。启用浏览器扩展后，扩展只从用户明确授权的官方页面读取完成提醒所必需的最小状态，并仅写入本机。
>
> **准确性与时效**  
> 排班不等于实时号源；“有号/已满”仅表示页面在标注检测时间的可见状态，可能因缓存、并发预约、退号、停诊或官方系统变化而失效。最终信息及预约结果以医院或北京 114/京通官方页面为准。
>
> **第三方访问与开源许可**  
> 本项目的开源许可证只授予本项目代码的使用权，不授予访问、抓取或自动化任何第三方网站、App、小程序或接口的权利。使用者和适配器贡献者必须遵守适用法律、官方用户协议、技术限制和频率要求；遇到验证码、访问拒绝或频控应立即停止。
>
> **非医疗建议**  
> 本项目只提供就医信息提醒，不提供诊断、治疗建议或医疗服务。急症请立即联系急救服务或前往医院急诊。

## 8. 开源适配器合入门槛

每个真实适配器 PR 必须同时提交：

1. 官方顶层来源 URL、页面标题、最后人工核验日期和截图/脱敏 fixture；
2. 数据等级（A0/A1/B/C/D）及为何不需要更高权限；
3. 默认频率、最小频率、随机抖动和指数退避；
4. 403/418/429、验证码、登录失效、空页面、DOM 改版时的 fail-closed 测试；
5. 证明不会读取或记录 Cookie、Token、身份证、医保、病历、手机号和支付信息的测试；
6. 不自动点击“预约/确认/支付”的测试；
7. 删除适配器的远程 kill switch 不应存在；但本地配置必须可立即停用和清除数据；
8. 禁止提交抓包记录、真实账号、真实患者数据、私有接口签名算法或反检测代码。

**最终建议：首版以协和公开皮肤科“新排班发布”适配器作为真实数据证明；把“实时有号”标记为默认关闭的本地 Browser Agent 实验能力；同仁鼻科先做规则、官方候补/跳转与定时提醒，其他医院不进入首版范围。不要为了补齐功能承诺而把未公开接口包装成 API。**
