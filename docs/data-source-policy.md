# 数据来源政策

本政策规定北京挂号雷达可以访问哪些来源、可以做出哪些结论，以及真实适配器进入稳定版本前必须提供哪些证据。

本项目是独立开源的本地信息提醒工具，与北京协和医院、北京同仁医院、北京 114、京通及其技术服务商不存在隶属、授权、合作或代理关系。医院、平台名称和商标仅用于标识信息来源。

## 基本原则

- 只读取完成提醒所需的最少公开信息。
- 优先使用医院官方顶层页面，不把未文档化站内请求称为开放 API。
- 访问频率服从官方规则、页面提示、`Retry-After` 和更严格的本地上限。
- 失败时停止推断，返回 `unknown`，不把失败写成“无号”。
- 排班不等于号源。排班、可预约状态、剩余数量和退号是不同事实，不能互相推导。
- 所有预约动作都在官方渠道由用户本人完成。
- 开源许可证只涉及本项目代码，不授予访问第三方网站、App、小程序或接口的权利。

本政策依据 [`source-research.md`](source-research.md) 中截至 2026-07-19 的官方来源研究。医院规则、页面和条款会变化，适配器仍需持续核验。

## 当前真实支持范围

| 来源 | 等级 | 自动访问 | 可以产生 | 明确不能产生 |
|---|---|---|---|---|
| 北京协和医院公开皮肤科周排班页 | A1 | 低频读取官方顶层页面渲染后的公开 DOM | `schedule_released`、排班新增、排班取消、可解释的排班内容变化 | `available`、`unavailable`、剩余数量、`availability_changed_to_available`、`cancellation_slot_detected` |
| 北京同仁医院崇文门院区鼻科 | A0/C | 规则复核可以低频访问官方公告；号源自动请求为 0 | 放号规则、核验时间、放号前提醒、官方预约和候补入口 | 实时排班、实时有号、退号、自动读取微信小程序或 114 会话 |
| Fixture 和演示来源 | 测试 | 只访问本地测试服务 | 状态机、去重、通知和故障流程 | 任何真实医院结论 |

首个真实适配器只承诺识别协和公开页面中的新排班发布，不检测排班移除。同仁鼻科首版只提供规则提醒。README、界面、通知、Release Notes 和演示必须保持一致。

## 来源等级

### A0：官方规则元数据

包括医院公告、放号时间、可预约天数、院区、科室、官方入口和候补说明。

- 常规复核不高于每 24 小时一次。
- 已稳定记录的规则可以每 7 天人工复核。
- 保存来源 URL、页面发布日期、最后核验时间和内容哈希。
- 不镜像与提醒无关的大段页面内容。

### A1：无需登录的官方公开排班页

包括页面直接公开的医生、职称、院区、日期、上午/下午、停诊和排班状态。

- 默认检查间隔不低于 2 小时。
- 已知排班发布窗口可以缩短到 30 到 60 分钟，窗口外恢复低频。
- 单域名并发为 1，多任务复用同一次结果。
- 加入随机抖动，避免所有本地实例在整点同时访问。
- 页面只公开排班时，适配器不能输出余号状态。
- 协和排班正文解码后最多读取 2 MiB；绝对 deadline 必须覆盖响应正文和每个 Playwright 步骤。
- CLI live probe 与服务端复用持久 `source_runtime` cooldown，不能通过重启脚本绕过两小时最小间隔。

### B：用户本机浏览器会话

B 级不是首版真实承诺。未来只有在用户显式启用、官方页面允许、真实会话 PoC 通过时才可加入。

仓库中的 MV3 Browser Agent 目前只是**默认关闭的实验性安全骨架**，selector allowlist 尚待真实会话验证；它的存在不表示协和、同仁或北京 114 的实时号源已经受支持。任何上下文、验证码或结构判断不完整时必须返回 `unknown`。

- 只在用户自己的电脑和自己的官方会话中运行。
- 默认 10 到 15 分钟一次；放号前后最多 30 分钟的窗口可缩短到 3 到 5 分钟。
- 医院 Cookie、医院会话 Token、身份证、医保卡、病历、候诊和支付信息不能离开浏览器资料目录，也不能写入 SQLite 或日志。Browser Agent 配对 token 不是医院凭证，仅用于扩展与 `127.0.0.1` 服务之间的 HMAC 身份证明和 Bearer 鉴权。
- 只向同机主进程返回规范化结果。
- 扩展使用至少 16 字节随机 base64url nonce 完成 HMAC-SHA256 challenge；challenge 不携带 token，每次 observation Bearer 提交前必须重新验证服务 proof。
- 不自动点击预约、候补、确认或付款。
- 出现验证码、登录过期、设备校验或访问拒绝时立即停止，状态为 `unknown`。

任何 B 级适配器都需要独立的用户确认、威胁模型、隐私测试和 7 天低频观察，不能因为项目只在本地运行而跳过审核。

### C：受限客户端或小程序

仅微信、支付宝、抖音小程序或其他受限客户端可见时：

- 自动请求为 0。
- 不抓包、不逆向私有协议、不模拟签名或设备。
- 不自动处理验证码或实名流程。
- 只保存官方规则、入口说明和定时提醒。

### D：正式合作 API

只有医院或平台书面授权、提供文档、鉴权、频率和数据处理约定时才使用。当前没有发现面向本项目的此类公开入口。

## 状态与事件口径

### 排班

排班表示医生或门诊单元在某日期和时段有公开出诊安排。排班不能证明：

- 当前可以预约。
- 还有剩余数量。
- 预约渠道已经开放。
- 用户具备预约资格。

协和公开适配器只能报告新排班发布；排班移除、停诊或号源状态都不在首版能力内。

### 有号与无号

只有官方来源明确展示“可预约”“有号”“剩余数量大于 0”时，才能规范化为 `available`。只有来源明确展示“约满”“无号”“剩余数量为 0”时，才能规范化为 `unavailable`。

当前首版真实适配器没有满足这一条件，因此真实产品不得产生“从无号变为有号”提醒。Fixture 中的同名状态必须标注为测试。

### 退号

只有同一稳定号源键在近期从明确 `unavailable` 变为明确 `available`，且已有足够上下文证明排班此前发布，系统才可以提示“疑似退号回流”。即使满足，也不能写“确定退号”。

当前首版真实适配器不提供明确有号状态，因此不支持真实退号检测。对同仁和协和已满场景，应优先提示用户使用官方候补渠道。

### 未知

以下情况统一返回 `unknown` 或来源错误，不得返回 `unavailable`：

- 网络超时、DNS 失败、连接中断。
- 403、418、429、5xx。
- 登录墙、验证码、设备校验。
- 页面为空但不符合合法空排班结构。
- 必需字段缺失或 DOM 结构变化。
- 数据不完整、含义不确定或检测时间不可确认。

`unknown` 不覆盖最近一次明确状态，也不触发有号、退号或新排班发布事件。

## 访问方式

### 官方顶层页面

真实适配器访问用户可以在浏览器中直接打开的官方顶层页面。即使页面内部使用片段请求，也不直接绑定未文档化的内部 URL，不把它包装成稳定 API。

优先使用 Node.js 内置 `fetch`。公开内容必须渲染时，才按需启动 Playwright Chromium，使用临时、无登录 Context 读取 DOM。

### 域名与重定向

每个适配器 manifest 必须声明：

- 官方主域名。
- 页面需要的静态资源域名。
- 支持的医院、院区、科室。
- transport、最小间隔、超时和可产生事件。

每次重定向都要重新校验协议、域名和解析地址。禁止访问：

- loopback、私网、链路本地和云元数据地址。
- `file:`、`data:`、`javascript:` 等非 HTTPS scheme。
- 用户输入的任意采集 URL。
- manifest 未声明的第三方追踪或广告域名。

### 频率与退避

来源策略必须采用更严格者：官方限制、页面提示、HTTP 响应或本政策。

- 单来源并发固定为 1。
- 多个任务共享相同查询结果。
- 429 优先遵守 `Retry-After`，且不能早于本地最小间隔。
- 403、418、验证码和结构变化不自动重试轰炸。
- 连续失败采用持久退避，恢复后仍从低频开始。
- 用户界面不提供突破最小间隔的轮询配置。
- 已知放号时刻不进行高频突发刷新，放号前提醒由本地规则产生。

## 数据最小化

适配器结果只保留完成变化判断所需的白名单字段：

- 来源、医院、院区、科室。
- 医生展示名或职称，页面明确公开时才保存。
- 日期、时段、排班状态。
- 来源真实支持时的规范化可用性。
- 检测时间、最后成功时间、内容哈希。
- 经过白名单校验的官方入口。
- 结构化、脱敏的错误码。

禁止保存：

- 原始 HTML 和完整响应正文。
- 医院侧完整请求头、Cookie、Set-Cookie、Authorization、会话 Token；Browser Agent 配对 token 也不得写入日志或 SQLite。
- 患者姓名、手机号、身份证、医保卡、病历、候诊、订单和支付信息。
- 浏览器 profile、storage state、截图、视频和 Trace。
- 含敏感查询参数的 URL。
- 为调试方便而保留的真实会话材料。

Fixture 也遵守同一规则。无法可靠脱敏的样本不能进入 Git。

## 失败与暂停

适配器必须 fail-closed。遇到来源变化时：

1. 停止输出新的排班或可用性结论。
2. 记录脱敏错误码、最后尝试时间和最后成功时间。
3. 将来源标记为降级或不可用。
4. 按持久退避等待，不提高频率。
5. 保留官方入口，提示用户自行查看。
6. 修复后先建立基线，不把不可观测期间的差异当作事件。

若官方条款变化、医院提出停止要求、页面新增验证码或访问行为影响正常服务，维护者应在下一个版本停用适配器。用户也必须能在本机立即停用来源。

## 适配器合入门槛

每个真实适配器 PR 必须提供：

1. 官方顶层 URL、页面标题、人工核验日期和来源等级。
2. 支持字段与明确不支持字段。
3. 最小访问间隔、抖动、退避和并发策略。
4. 公开页面正常、合法空结果和结构变化 Fixture。
5. 403、418、429、5xx、超时、登录墙和验证码测试。
6. 域名、重定向、私网和云元数据拦截测试。
7. 隐私金丝雀扫描，覆盖 SQLite、日志、Fixture 和测试产物。
8. 不自动预约、确认、候补提交和付款的网络审计。
9. 人工同屏比对，证明规范化字段与官方页面一致。
10. 本地停用、数据清理和回滚说明。

选择器能工作不等于适配器可合入。没有官方证据、失败路径和可重复测试的适配器不会进入稳定 Release。

## 用户可见文案

允许：

- “检测到协和公开页面出现新排班”
- “官方页面出现新的出诊安排”
- “当前结果未知，上次成功检测时间为……”
- “同仁鼻科当前仅支持规则提醒”
- “请前往官方渠道确认”

禁止：

- “协和有号”
- “发现协和退号”
- “同仁实时余号”
- “已抢到”“锁定号源”“预约成功”
- “官方 API”，除非确有面向第三方的公开文档和授权
- 把 Fixture、演示或手工录入状态描述成 live 结果

每条提醒都应包含来源、检测或核验时间、能力边界和官方入口。

## 官方预约边界

用户点击官方入口后，本项目停止自动操作。登录、验证码、实名、医保、候补、确认和付款全部由用户在官方渠道完成。

本项目不保证用户打开页面时仍有相同排班或状态，不保证官方入口持续可用，也不提供诊断或治疗建议。急症应联系急救服务或前往医院急诊。

本政策是产品和工程约束，不构成法律意见。适配器维护者和使用者仍需遵守适用法律、官方用户协议和技术限制。
