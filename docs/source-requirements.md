# 北京挂号雷达 · 需求来源摘要

> 来源：https://chatgpt.com/s/t_6a5ba16565b081918ad32211816a916b
> 提取日期：2026-07-18

## 产品定位

定位为「挂号信息聚合 + 放号提醒 + 退号监控」，不做自动抢号器。

核心边界：

1. 聚合并标注官方信息来源；
2. 记录医院、院区、科室的放号规则及最后核验时间；
3. 低频、克制地查询公开号源状态；
4. 变化后及时通知；
5. 跳转官方渠道，由用户人工完成验证码、实名、医保、确认和付款；
6. 不绕过风控、不使用多账号并发、不使用代理 IP 轮换；
7. 不上传医院 Cookie、Token、账号密码，不保存身份证或医保卡。

## MVP 目标对象

- 北京同仁医院崇文门院区鼻科；
- 北京协和医院或北京大学第一医院皮肤科；
- 支持指定医生、职称条件或任意可用专家号；
- 支持未来 7～14 天、上午/下午、院区偏好。

## MVP 功能

### 1. 放号规则日历

每条规则包含：医院、院区、科室、提前预约天数、常规放号时间、当日剩余号规则、官方入口、信息来源、最后核验时间、可信度、是否需要重新确认。

### 2. 关注任务

用户可按医院、院区、科室、医生/职称、日期范围、上午/下午和事件类型建立、启停、编辑、删除任务。

事件类型：

- `schedule_released`
- `availability_changed_to_available`
- `cancellation_slot_detected`

### 3. 提醒

- 定时提醒：放号前 5 分钟；
- 状态提醒：从无号变为有号；
- 通知提供检测时间、号源摘要及官方预约入口；
- 同一变化需要去重和冷却。

### 4. 适配器与监控

- 医院变化隔离在 `SourceAdapter` 层；
- 保存脱敏的可用性快照和内容哈希；
- 适配器健康检查、失败原因和最后成功时间可见；
- A 级数据：无需登录的官方公开页面/接口；
- B 级数据：用户本机浏览器会话，仅上传脱敏的有号/无号结果；
- C 级数据：仅微信小程序可查时，先提供规则和定时提醒，不逆向私有接口。

### 5. 交付与运维

- 简洁但可完整操作的 Web 管理端；
- PostgreSQL、Redis、Worker、Playwright Browser；
- Docker Compose 一键启动；
- 真实通知渠道至少一个；
- 具备自动化测试、健康检查和可重复的演示/验收数据流。

## 明确不做

- 自动提交预约；
- 验证码识别或绕过；
- 多用户 SaaS；
- 代理池与高频轮询；
- 批量账号与抢占号源；
- 保存完整医疗档案或敏感身份信息。

## 当前待决策

- 首版是个人私有版、稳定开源版，还是本地优先混合版；
- 首个真实通知渠道；
- 首批真实数据来源能否稳定公开访问，或是否需用户本地浏览器 Agent；
- 部署目标（仅本机 / NAS / 云服务器）。
