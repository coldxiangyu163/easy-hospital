# Design System — 北京挂号雷达

## Product Context

- **What this is:** 个人私有的北京医院挂号信息聚合、放号规则与变化提醒工具。它帮助用户减少反复刷新和记忆规则的负担，但绝不自动抢号或代替用户提交预约。
- **Who it is for:** 需要持续关注特定医院、院区、科室、医生或职称与未来 7–14 天日期窗口的北京就医用户及家属。
- **Space:** 医疗信息工具、个人健康助理、变化监控。
- **Project type:** 桌面优先、窄屏兼容的高保真 Web 产品原型。

## Shared Trust Contract

- 所有非生产数据必须显式标注“演示数据”。
- 不假设存在未经确认的实时号源 API；公开页面可用性与真实余号必须在官方渠道重新核验。
- 每条规则或变化必须同时展示来源、最后核验时间、可信度、接入等级 A/B/C。
- A 级表示无需登录的官方公开页面或接口，可监测公开排班发布与排班变化；A 级不等于实时有号。
- B 级表示用户本机浏览器已有官方会话；Browser Agent 只向 `127.0.0.1` 返回脱敏的“有号 / 无号 / unknown”，Cookie 与 Token 不离开本机、不写入产品数据库。
- C 级表示来源仅存在于小程序或不可合规读取；产品只提供已核验规则、放号前提醒与官方入口，不逆向、不抓取、不推断实时号源。
- 产品只保存完成提醒所需的最少信息，不收集身份证、医保卡、就诊人完整身份信息。
- 所有预约动作在官方渠道由用户手动完成。

## MVP Scope And Runtime

- 首批目标仅包含：北京同仁医院崇文门院区鼻科、北京协和医院皮肤科。
- 协和公开排班只表达 `schedule_released` 与排班变化，不显示实时有号、无号或退号结论。
- 同仁鼻科默认使用 C 级规则提醒，并保留官方候补入口。
- 产品以稳定开源、本地运行交付；无 Docker、无云端服务、无遥测。
- 本地持久化使用 SQLite 单进程；密钥与凭据在界面中只显示“已配置 / 未配置”。

## Direction A — 专业医疗控制台

- **Aesthetic:** 冷静、可信、偏临床运营台；浅色冷灰画布、白色工作面板、深海军蓝文字、单一医疗蓝强调。
- **Typography:** PingFang SC / Microsoft YaHei 作为正文与界面；SF Mono / Menlo 用于时间、等级、状态和值。
- **Color:** `#F4F7FA` 背景、`#FFFFFF` 面板、`#142033` 文字、`#657083` 辅助、`#DDE4EB` 边界、`#1769E0` 强调。
- **Layout:** 固定侧栏 + 顶部任务上下文 + 12 列工作区；8px 基础间距，6/10/14px 分级圆角，hairline border，不使用装饰阴影。
- **Motion:** 140–220ms 的功能性过渡，只解释页面切换、加载和确认。
- **Risk:** 把来源与核验信息提升到一级视觉层级，牺牲一点轻松感，换取可审计性。

## Direction B — 温暖克制的个人健康助理

- **Aesthetic:** 安静、清楚、低刺激；偏冷的米白与灰绿，而非甜腻粉橙或营销感渐变。
- **Typography:** STSong / Songti SC 用于关键结论与引导标题；PingFang SC 用于正文；SF Mono 用于时间与可信度。
- **Color:** `#F7F6F1` 背景、`#FFFFFF` 面板、`#26302C` 文字、`#6C746F` 辅助、`#E3E1D9` 边界、`#2C7865` 强调。
- **Layout:** 顶部阶段导航 + 720–1040px 单列叙事流；更大的 16/24/32px 间距，用“你现在需要知道的事”取代监控术语。
- **Motion:** 柔和但克制的进入/展开，持续 180–260ms；无弹跳和无意义动效。
- **Risk:** 用自然语言解释数据状态，牺牲部分密度，换取焦虑场景下的可理解性。

## Direction C — 高密度雷达监控台

- **Aesthetic:** 深色、工业化、信息密度优先；接近网络监控与交易终端，而非消费级 dashboard。
- **Typography:** PingFang SC 用于短标签；SF Mono / Menlo / IBM Plex Mono 作为主数据字体，全部数字启用 tabular-nums。
- **Color:** `#071019` 背景、`#0C1722` 面板、`#DCE8F2` 文字、`#71879A` 辅助、`#203244` 边界、`#39C6A3` 强调。
- **Layout:** 顶部命令条 + 三栏监控面板 + 紧凑数据行；2/4/8/12px 间距，2/4/6px 圆角，网格线与状态灯只表达运行状态。
- **Motion:** 80–160ms，尽量即时；实时感由时间轴与变化日志构成，不用环境光或渐变。
- **Risk:** 极高密度和暗色在长时间监控中更高效，但初次用户学习成本更高。

## Shared Responsive Rules

- Desktop ≥ 1180px：保留方向特有的完整信息架构。
- Tablet 760–1179px：侧栏收窄或转为横向阶段导航；多栏降为两栏。
- Narrow < 760px：单列内容、底部或横向可滚动导航、44px 最小点击目标，不把桌面表格简单压缩。
